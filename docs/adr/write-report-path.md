# 同じ単一パスへの書き込み報告では file を省略する

## 状況

write は、入力に指定したパスを `file` として毎回報告していた。対象が一意に分かる書き込みでは同じ情報を繰り返し、特に絶対パスで出力が長くなる。

## 決定

- CLI と MCP の write は、すべての入力が同じパス文字列を指し、そのパスが glob でなければ、成功・失敗の報告から `file` を省く。同じパスへの複数編集も含む。
- 入力が glob、または複数のパスなら `file` を残す。実際に書けたファイルの数だけでは省略を決めない。
- 遅れて届いた整形や診断の報告は、その呼び出しの入力と別のファイルについての場合があるので、引き続きパスを付ける。
- MCP の変更検知は、省略されたパスを入力から補う。

## 結果

- 得たもの: 対象が分かっている報告が短くなり、繰り返しのパスに使う token が減る。
- 失ったもの: 単一パスの報告だけを取り出すと、対象ファイルが分からない。常に `file` があることに依存する利用側は、入力から補う必要がある。

## 採らなかった案

- 報告が 1 件なら常に省く: glob の対象や、別のパスへの失敗を識別できなくなる。
- 成功時だけ省く: 失敗時も入力から対象が分かり、繰り返す必要がない。
