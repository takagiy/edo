# read の行範囲は末尾で切り詰め、範囲外なら空で成功させる

## 状況

ファイルの行数を知らずに大きめの範囲を読むと、`out_of_range` が返り、行数を知ってから読み直す必要があった。複数のファイルを読むと、この往復がファイルごとに増える（[アイデア](../idea/fewer-calls.md)）。

## 決定

- CLI と MCP の `read` は、行範囲の終わりが末尾を越えたら末尾まで返す。切り詰めたことは報告せず、エラーや警告にしない。
- 始まりも末尾を越えていたら、空で成功する。空のファイルも同じ扱いにする。
- 複数のスコープや glob でも、行範囲ごと、ファイルごとに同じ規則を適用する。
- `0` や逆順の行範囲は、引き続き入力エラーにする。
- `write` は範囲を厳密に検証する。末尾を越える指定はエラーにし、ファイルを変えない。

## 結果

- 得たもの: 行数の確認や読み直しが要らなくなる。エラーや警告の出力も増えない。
- 失ったもの: 末尾を越える指定ミスをエラーで検出できなくなる。空の結果だけでは、空ファイルと範囲全体が末尾より後の場合を区別できない。

## 採らなかった案

- 切り詰めたことを警告する: 行数を知らずに読む通常の操作で出力が増える。
- 始まりが末尾を越えた場合だけエラーにする: 読める行がない場合も成功として扱う方針に合わない。
- `write` も切り詰める: 指定した範囲と違う箇所を書き換えるおそれがある。
