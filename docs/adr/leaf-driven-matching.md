# before の照合はファイルの構文木の葉を基準にする

## 状況

`write` の `before` は、インデントやコードスタイルの違いを無視して照合したい。`before` は途中で切れた断片のこともある。

## 決定

対象ファイルを tree-sitter でパースして葉を並べ、葉を 1 つずつ進めながら `before` の文字を前から消費する。`before` はパースしない。

- 葉と葉の間の空白は任意。ただし単語の葉が続く箇所では `before` にも空白が必要。
- 葉のテキストは完全一致が既定。言語ごとの緩和は `edo.scm` のキャプチャで宣言する: `@match.optional`、`@match.trailing`、`@match.quote`（`#set! alt`）、`@match.collapse`。
- `before` の先頭は葉の後半、末尾は葉の前半に一致してよい。
- 一致がなければ、最も長く消費できた位置と食い違いを `closest` として返す。

## 結果

- 得たもの: 断片が文字列やコメントの途中から始まっても動き、フォールバックが要らない。文字列の中身の空白は正確に比べられる。
- 失ったもの: 省略可能な葉があるので小さなバックトラックが要る。`before` 側にだけある optional の葉は、ファイルに同じテキストの optional 葉があるときしか読み飛ばせない。

## 採らなかった案

- 空白で区切る単純なトークン照合: 構文を知らない照合は edo のコンセプトに合わない。
- `before` も tree-sitter でパースする: 断片が文字列の途中から始まると字句分割が崩れる。
