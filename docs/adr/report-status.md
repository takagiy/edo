# 外向けの報告から ok を省き、error で失敗を示す

## 状況

成功の報告には `replaced` などの結果があり、失敗の報告には必ず `error` がある。`ok=true/false` はそれらと情報が重なる。一方、CLI の終了コードや MCP の `isError`、書き込み済みファイルの記録などは、内部の `ok` で判定している。

## 決定

- 共通の MISON 出力処理で `ok` を省略する。配列内の報告も同じ扱いにし、内部の値は変えない。`installed=false` など、別の意味を持つ真偽値は残す。
- 失敗は `error` と詳細で示し、成功は `replaced` などの結果で示す。複数編集の失敗は `file` や `item` で対象を識別する。
- 整形の失敗は `warnings.format_failed` にする。書き込み自体の成功とは分け、構文や LSP の追加エラーも引き続き警告として報告する。
- CLI の終了コードと MCP の `isError`、hook の JSON は変えない。

## 結果

- 得たもの: 成功・失敗とも報告が短くなる。書き込みの失敗と、書き込んだ内容への警告を区別できる。
- 失ったもの: MISON を読む利用側は `ok` による一律の成否判定ができなくなる。`warnings.format` を読んでいた利用側も名前の変更に対応する必要がある。

## 採らなかった案

- `ok=false` だけ残す: 失敗は `error` で分かるので重複が残る。
- 内部の `ok` も削除する: 終了コードや MCP の判定まで変える必要があり、報告を短くするためには要らない。
