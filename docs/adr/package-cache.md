# 既知のレジストリとインストール済みのパッケージを edo-cache.toml に記録し、これを正とする

## 状況

`edo lang install` を引数なしで起動すると、既知のレジストリのパッケージを並べた対話画面から選んでインストールできるようにしたい。そのためには、どのレジストリが既知か、それぞれにどのパッケージがあるか、どれがインストール済みかを知る必要がある。これまではインストール先のフォルダをたどって読み込み、入手元は各パッケージの `.edo-source` に書いていた。

## 決定

- `<config>/edo/edo-cache.toml` に `[[registries]]`（`type`、`repo`、パッケージの一覧を読んだ `commit`、`packages`）と `[[packages]]`（`registry`、`name`、`commit`）を書く。
- インストール済みかどうかは `[[packages]]` で決める。一覧、読み込み、削除はこれを見る。`.edo-source` は廃止した。
- ファイルがなければ、デフォルトのレジストリだけが既知になる。インストールや `edo lang registry add` でレジストリを取得すると既知になり、パッケージの一覧が記録される。`edo lang registry remove` で外しても、そこから入れたパッケージは残る。
- 対話画面はキャッシュした一覧を表示する。一度も取得していないレジストリだけ起動時に取得し、U ですべてを取得し直す。続けてもう一度 U を押すと、インストール済みのパッケージを最新のコミットから入れ直す。
- 対話画面はチェックの状態を「入っていてほしい状態」とみなし、確定すると外したものを削除してから選んだものを入れる。
- 画面は stderr に描き、stdout には他のコマンドと同じ JSON の報告だけを出す。端末でないところから引数なしで呼ぶと usage エラーにして、エージェントが画面で止まらないようにする。

## 結果

- 得たもの: 対話画面がすぐ開き、オフラインでも一覧を見られる。インストール済みかどうかの情報が 1 か所にまとまり、フォルダと食い違わない。
- 失ったもの: 手でフォルダを置いただけのパッケージは読み込まれない。古い形式（`.edo-source`）で入れたパッケージは入れ直しが要る。キャッシュした一覧は U を押すまで古いままになる。`edo-cache.toml` はロックせずに読み書きするので、同時に動かした `edo lang` は記録を取りこぼすことがある。
- 採らなかった案: 起動のたびにすべてのレジストリを取得する案は、一覧が常に新しい代わりに毎回通信を待つので採らなかった。フォルダを正のままにして記録だけ足す案は、情報が 2 か所に分かれて食い違うので採らなかった。レジストリをインストールで使ったときだけ既知にする案は、まだ何も入れていないレジストリを画面に出せないので、登録コマンドも足した。
